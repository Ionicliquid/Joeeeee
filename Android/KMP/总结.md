# 重组
1. 重组的本质：当状态（State）改变时，Recomposer 调度受该状态影响的 Composable 函数重新执行。这个过程就是“重组”。在这个过程中，涉及到 3个对象：State ,Recomposer,Composer；
2.  状态State关联 快照，组合成 SnapshotState，快照有 2 个作用
	1. 对状态的读写进行隔离，composing 时创建全局快照的子快照，调用 enter进入快照，通过snapshotId 控制，快照上只能访问创建时的最新状态，子快照内对状态的修改需要 主动调用apply提交到全局快照；
	2. 状态读写感知，Composable函数内对状态的读写都会被记录，作为重组的依据；
3. Recomposer ：setContent时创建，启动时注册全局快照状态监听，并开启协程监听 Vsync 信号，发起并驱动重组流程，无变更内容时会挂起等待；
4. RecomposeScopeImpl：重组作用域，记录了对应的Composable函数，当其读取的状态变化时，标记该函数需要重组；
## 自定义布局
Compose 实现自定义布局有 4 种方式
1. 使用 Canvas自定义绘制，类似于传统 View 的 onDraw 方法，通过 drawRect drawCircle drawPath 等方法绘制各种图形；
2. 使用 Layout自定义布局，类似于传统 View 的 onMeasure与 onLayout的结合，核心 API 是measurable与placeable用于测量大小和拜访位置
	1. 流式布局
3. Modifier 的drawWithContent方法，在已有布局上叠加效果
4. 通过 `AndroidView`，你可以将传统的 `View` 嵌入 Compose 布局中，复用 XML 布局中已有的自定义视图。
