# 声明式UI
1. 描述 UI 与状态的关系状态，当状态发生变化下，UI自动更新；
2. 如何实现 Button点击，TextView 计数的功能
	1. 在命令式 UI中，需要监听 Button的点击，点击时，修改 TextView 的显示
	2. 而在声明式 UI 中，Button 点击修改状态，TextView 描述状态的关系，自动响应状态变化。
## MVI
1. Model：表示 UI的状态，是唯一的数据源；
2. View：接收一个 状态对象并渲染 UI，并将用户输入作为 **Intent** 发送
3. Intent：表示用户的操作意图（如点击按钮、输入文本）
4. ViewModel：接受 Intent,处理业务逻辑更新 State;
5.  MVI 强调的是“唯一可信数据源”与“单向数据流”
	1. 唯一可信数据源：
		1. 唯一的意思不是说一个页面一个状态，而是将界面分成若干个相互独立的状态，控件状态不会相互影响；
		2. 可信的意思是它是线程安全且不对外暴露修改方法，在 Android 中的实践就是采用 val 修饰，多线程写变量的时先拷贝源变量，然后对副本写。
		3. 单向数据流是指数据只能沿着一个方法流动，形成闭环。在 MVI 中就是，View 产生 Intent 触发 状态更新后 View 重新渲染；
6. 和 MVVM相比，严格限制单向数据流和唯一可信数据源，结合 Composable 函数，更容易测试
# Compose 的 UI 组织形式
1. @Copmposable 函数经过编译后生成的函数会添加 2 个参数，类型为 Composer 与 Int。
2. 函数内部插入了很多 `$composer.startXXXGroup` 和 `$composer.endXXXGroup` 模板代码；composer 的作用就是就是将 UI 结构，状态信息记录到 SlotTable 中；
3. SlotTable 的数据存储在 Slot 中，一个或多个 Slot 又归属于同一个 Group;布局信息对应的 LayoutNode也会被插入对应的 Slot 中；
4. 多个LayoutNode 组合生成 Compose 的渲染树，完成测量，布局和绘制工作；
5. UI 的变化本质是触发更新 LayoutNode 树，重新渲染布局；

# 重组
1. 重组的本质：当状态（State）改变时，Recomposer 调度受该状态影响的 Composable 函数重新执行。这个过程就是“重组”。在这个过程中，涉及到 3个对象：State ,Recomposer,Composer；
2.  状态State关联 快照，组合成 SnapshotState，快照有 2 个作用
	1. 对状态的读写进行隔离，composing 时创建全局快照的子快照，调用 enter进入快照，通过snapshotId 控制，快照上只能访问创建时的最新状态，子快照内对状态的修改需要 主动调用apply提交到全局快照；
	2. 状态读写感知，Composable函数内对状态的读写都会被记录，作为重组的依据；
3. Recomposer ：setContent时创建，启动时注册全局快照状态监听，并开启协程监听 Vsync 信号，发起并驱动重组流程，无变更内容时会挂起等待；
4. RecomposeScopeImpl：重组作用域，记录了对应的Composable函数，当其读取的状态变化时，标记该函数需要重组；
## 自定义布局
Compose 实现自定义布局有 4 种方式
1. 使用 Canvas自定义绘制，类似于传统 View 的 onDraw 方法，通过 drawRect drawCircle drawPath 等方法绘制各种图形；
2. 使用 Layout自定义布局，类似于传统 View 的 onMeasure与 onLayout的结合，核心 API 是measurable与placeable用于测量大小和拜访位置
	1. 流式布局
3. Modifier 的drawWithContent方法，在已有布局上叠加效果
4. 通过 `AndroidView`，你可以将传统的 `View` 嵌入 Compose 布局中，复用 XML 布局中已有的自定义视图。
